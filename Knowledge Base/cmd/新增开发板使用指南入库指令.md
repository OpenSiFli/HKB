# MCU开发板使用指南导入、知识库归档处理指令提示词
## 前置约束
1. 当前Obsidian Vault已搭建企业全系列MCU硬件知识库，根目录`AGENTS_MCU_ALL.md`为最高运维规范，所有操作严格遵守该文件全部条款；
2. 待导入文件路径：【替换开发板指南完整raw路径，示例：raw/mcu/ref_design/DEV-XX32F103-V1开发板使用指南.pdf】
3. 文档类型：MCU开发板硬件使用指南，包含开发板板载电路、外设资源、硬件接线、测试方法、调试操作、硬件跳线配置、供电方案、扩展接口规范、硬件故障排查、量产参考设计参考依据
4. 文档定位：实物开发板配套实操文档，作为硬件设计参考、研发调试、图纸审图比对、售后问题排查辅助资料。

## 一、核心任务目标
1. 完整拆解开发板指南全部硬件相关内容，结构化归档至Wiki对应模块；
2. 提取开发板板载硬件电路作为标准参考电路，补充至对应MCU芯片实体页、外设规范页；
3. 提取跳线、拨码、BOOT、供电、调试接口硬性配置规则，生成辅助校验规则，用于原理图审图对标参考；
4. 整理开发板常见硬件故障、排查步骤存入故障案例库，用于研发问题检索；
5. 新建来源归档页，完善芯片、外设、参考电路双向双链，更新全局导航、变更日志；
6. 指南内容与芯片规格书、企业硬件设计指南冲突时，全部保留多版本内容，标注适用场景：开发板演示方案≠量产强制标准。

## 二、全维度提取拆解范围
### 1. 开发板基础信息与主控MCU绑定（更新chip_entity芯片实体页）
1. 开发板型号、硬件版本、搭载主控MCU完整型号、板载Flash/RAM资源；
2. 开发板供电方案：输入电压、板载LDO/DC-DC电路、各外设电源域、功耗参数；
3. 板载最小系统电路：复位、外部晶振、BOOT拨码/跳线、下载调试接口硬件原理图；
4. 板载外围基础器件：LED、按键、指示灯、存储、晶振、复位芯片等物料规格。

### 2. 板载所有外设硬件参考电路（批量更新peripheral外设库）
GPIO、ADC、DAC、UART、SPI、I2C、CAN、PWM、LCD、传感器接口等板载外设：
1. 开发板实际接线方案、上下拉/滤波/匹配器件参数；
2. 跳线、拨码开关配置逻辑、功能切换硬件条件；
3. 扩展引出引脚定义、外部拓展电路推荐方案；
4. 区分“开发板演示电路”与“量产产品标准电路”，明确标注不可直接量产复用的设计。

### 3. 开发板硬件操作、调试、测试规范（补充design_rules参考设计分区）
1. 上电顺序、多电源供电切换方法、外部拓展模块接线禁忌；
2. 下载调试硬件连接方式、仿真器适配要求、调试使能硬件条件；
3. 板载测试点使用方法、硬件测量点位、信号测试规范；
4. ESD防护、高低温测试实操注意事项。

### 4. 可复用/不可复用设计区分 & 原理图对标校验规则（补充check_rules参考类规则）
1. 提取开发板合规标准电路作为参考范本，生成参考型校验规则；
2. 标记开发板临时简化电路、演示专用电路，审图时提示“量产需按企业硬件设计指南修改”；
3. 每条规则标注：参考来源为开发板指南，仅作调试参考，不替代企业顶层设计规范。

### 5. 开发板典型硬件故障、排查方案（更新fault_case故障库）
1. 无法上电、下载失败、外设无输出、晶振不起振、IO异常等开发板高频问题；
2. 硬件根因、排查步骤、跳线/供电整改方案；
3. 同类量产图纸规避建议。

### 6. 研发调试报告、问题复盘标准话术（补充report_template）
提取开发板调试问题描述、硬件排查结论标准文案，支撑研发内部问题记录输出。

## 三、标准执行步骤（顺序不可打乱）
### 步骤1：全库预检索查重
1. 检索`wiki/mcu/all/sources/`，确认本开发板指南是否已归档，避免重复建页；
2. 检索`wiki/mcu/all/chip_entity/`找到开发板搭载的MCU芯片实体页面；
3. 预加载所有外设页面、校验规则、故障案例页面，准备增量补充参考内容。

### 步骤2：创建设备指南来源索引页 wiki/mcu/all/sources/
使用`_template.md`来源模板新建页面：
1. 绑定raw开发板指南双链链接，填写开发板型号、硬件版本、搭载MCU型号、发布日期；
2. 摘要说明文档定位：开发调试参考，非量产强制标准；
3. 记录核心硬件章节、跳线/原理图关键页码索引；
4. YAML元数据完整填充：`mcu_family`、`mcu_model`、`sources`、`tags: ["开发板","参考设计","调试指南","DEV板"]`；
5. 双向关联对应MCU芯片实体页面、外设总页面。

### 步骤3：更新对应MCU芯片实体页面 wiki/mcu/all/chip_entity/
1. 在芯片实体页新增板块「配套官方/自研开发板参考设计」，写入本开发板基础硬件信息；
2. 附上开发板最小系统原理图要点，标注为调试参考方案；
3. 建立双向双链关联开发板来源页。

### 步骤4：批量更新外设专项页面 wiki/mcu/all/peripheral/
1. 对每一个板载外设页面，补充本开发板配套参考电路、跳线配置参数；
2. 增加本开发板指南为页面来源引用；
3. 明确标注：该电路仅开发板演示使用，量产需遵循企业硬件设计指南。

### 步骤5：新增参考类原理图校验规则 wiki/mcu/all/check_rules/
1. 针对开发板标准参考电路新增参考对标规则；
2. 对开发板简化、临时电路增加风险提示规则，提醒量产改造；
3. 规则统一备注：参考依据为开发板使用指南，优先级低于硬件设计指南、芯片datasheet。

### 步骤6：更新故障案例库、设计参考库、报告模板库
1. 开发板硬件故障、调试异常存入`fault_case/`，绑定对应MCU型号与外设；
2. 开发板完整参考电路归档至`wiki/mcu/all/design_rules/ref_design/`；
3. 调试问题标准描述文案补充至`report_template/`。

### 步骤7：更新全局导航与变更日志
1. 修改`index_MCU_ALL.md`，新增「开发板参考设计」分类入口，链接本指南来源页与对应MCU；
2. 在`log_MCU_ALL.md`尾部追加操作记录，固定格式：
`YYYY-MM-DD | 导入资料：开发板指南raw完整路径 | 新建页面：页面清单 | 更新页面：页面清单 | 待人工确认：开发板方案与量产规范冲突明细`

### 步骤8：双链闭环自检
校验所有新建、修改页面双向关联双链，无断链、无效链接。

## 四、强制执行规则（对齐AGENTS_MCU_ALL.md）
1. Raw层开发板使用指南仅读取解析，禁止修改、移动、删除原始PDF；
2. 所有电路、配置、故障方案必须标注来源（开发板指南+页码）；描述模糊、缺少量化指标统一标记「待人工核实」；
3. 开发板电路与企业硬件设计指南、芯片手册存在冲突时，两套内容全部保留，明确区分优先级：企业硬件设计指南 > 芯片datasheet > 开发板演示电路；
4. 原有Wiki页面仅增量补充参考内容，不删除、覆盖历史规范，不修改其他MCU型号专属知识；
5. 指南描述模糊、无明确可落地量产标准，无法提炼校验规则时，立刻暂停执行并向我提问，禁止自行编造硬件参数；
6. 所有页面必须使用对应分类`_template.md`标准模板，YAML元数据必填字段完整；
7. 软件操作、代码示例仅简要记录，核心重点处理硬件电路、跳线配置、供电、调试接线、硬件故障排查相关内容。
