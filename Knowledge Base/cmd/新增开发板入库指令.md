# 开发板（Dev Board）结构化入库与 Wiki 生成指令提示词

## 前置约束
1. 当前 Obsidian Vault 已搭建企业全系列 MCU 硬件知识库，开发板作为与其**平级的一大类**独立管理；仓库根目录 `AGENTS_MCU_ALL.md` 的通用约束（Raw 只读、缺料即停不编造、增量补充、模板 YAML 必填）同样适用；
2. 待导入文件路径（主要依据）：【替换为开发板原理图完整 raw 路径，示例：raw/dev_board/schematics/DEV-SF32LB527-EVK_Sch_V1.0.pdf】；可选补充：PCB / BOM / GPIO 分配表 / 使用指南（对应 raw/dev_board/pcb/、bom/、gpio_table/、guide/）；
3. 文档类型：开发板原理图（EDA 导出的 PDF）为主，辅以 PCB、BOM、GPIO 分配表、使用指南；覆盖板载电源树、复位、时钟晶振、外置存储、BOOT、调试接口、外设、ESD 防护等完整参考电路与 BOM；
4. 文档定位：开发板实物参考电路，是原理图 AI 审图、硬件设计参考、故障分析的权威事实源头之一；与芯片 datasheet / 用户手册互补，不冲突；开发板演示电路 ≠ 量产强制标准。

## 一、核心任务目标
1. 将开发板原理图（及可选 PCB/BOM/GPIO/指南）经 EDA 矢量文本提取，结构化拆解为元件位号、参数、网络标号、引脚映射；
2. 在 `wiki/dev_board/all/sources/` 新建来源页，绑定 raw 双链；
3. 在 `wiki/dev_board/all/board_entity/` 建立开发板实体页，填写 11 项核心参数（平台 / 芯片 / 模组 / 上芯方式 / 存储配置 / 供电方式 / 外设 / 调试接口 / 适用场景 / 使用指南文档 / 图纸），并双向双链至对应 MCU 芯片实体页；
4. 在 `wiki/dev_board/all/schematics/` 建立图纸提取页，沉淀电源树/复位/时钟/BOOT/调试/存储/外设关键位号参数与 GPIO 分配；
5. 更新 `index_DEVBOARD_ALL.md` 与 `log_DEVBOARD_ALL.md`，输出自检清单。

## 二、全维度提取拆解范围
### 1. 原理图结构化提取（先执行 EDA 文本提取）
- 调用仓库根目录 `EDA原理图PDF识别提示词.md` 流程：优先 pdfplumber 矢量文本（方案A），检测失效后切换 PaddleOCR（方案B）；
- 提取要素：元件位号（R/C/U/L/D/Q…）、参数（阻值/容值/型号/耐压）、网络标号（VCC/GND/3V3/USB_D+…）、电源地标识、引脚编号、差分/总线标识；
- 输出结构化 JSON（含页码、坐标、置信度、可疑标记），禁止脑补虚构电路或参数；
- BOM / GPIO 分配表优先直接解析表格，补充关键器件选型与引脚分配。

### 2. 开发板 11 项核心参数 → Wiki 映射
- 平台（MCU 系列）→ `board_entity` §一 + 双链 `wiki/mcu/all/chip_entity/`；
- 芯片（具体型号）→ `board_entity` §二 + 双链对应芯片页面；
- 模组（具体型号）→ `board_entity` §三；
- 上芯方式（芯片/模组）→ `board_entity` §四；
- 存储配置（板载 Flash/RAM/扩展接口）→ `board_entity` §五 + `wiki/mcu/all/peripheral/SF32LB52X_Peripheral_Memory.md`；
- 供电方式（输入/电源树/去耦）→ `board_entity` §六 + `wiki/mcu/all/peripheral/SF32LB52X_Peripheral_Power.md` + `schematics` 提取页；
- 外设（板载与扩展）→ `board_entity` §七 + 各 `wiki/mcu/all/peripheral/` 页面（标注"开发板演示，量产以企业规范为准"）；
- 调试接口（SWD/UART/测试点）→ `board_entity` §八 + `wiki/mcu/all/design_rules/DR_Debug_Interface.md`；
- 适用场景 → `board_entity` §九；
- 使用指南文档 → `board_entity` §十 + raw/guide/ 双链；
- 图纸（原理图/PCB/BOM/GPIO）→ `board_entity` §十一 + `schematics` 提取页 + raw 双链。

### 3. 生成图纸提取页（schematics，关键产出）
- 电源树（BUCK/LDO/各电源域/去耦）→ 位号/参数/网络；
- 复位电路（POR/BOR/nRST 外接）→ 位号/参数；
- 时钟/晶振（48M 主晶振 + 32.768k RTC + 负载电容）→ 位号/参数；
- 外置存储（QSPI/SPI/SDRAM/eMMC 接口与电平/去耦，MPI/SDMMC 互斥）→ 位号/网络；
- BOOT 配置（strapping 电阻/跳线/电平）→ 位号/参数；
- 下载调试接口（SWD/UART 引脚、测试点、上拉）→ 位号/参数；
- 去耦/滤波/ESD 防护 → 位号/参数；
- GPIO 分配表 → 功能/引脚/网络/备注表格；
- BOM 关键器件 → 型号/供应商，关联 `raw/mcu/vendor/device_spec/` AVL。

## 三、标准执行步骤（顺序不可打乱）
### 步骤1：全库预检索查重
1. 检索 `wiki/dev_board/all/sources/`、`wiki/dev_board/all/board_entity/`，确认本开发板是否已归档，避免重复建页；
2. 检索 `wiki/mcu/all/chip_entity/` 定位本板搭载的 MCU 平台/芯片页面，准备双链；
3. 预加载相关 `peripheral/`、`design_rules/`、`check_rules/` 页面，准备引用。

### 步骤2：EDA 原理图 PDF 文本提取
依 `EDA原理图PDF识别提示词.md` 生成结构化 JSON（方案A 优先），作为后续拆解事实依据；保留页码/坐标用于溯源；BOM/GPIO 表优先直接解析。

### 步骤3：新建来源索引页 wiki/dev_board/all/sources/
使用 `_template.md`（type: dev_board_source）新建页面：
1. 绑定 raw 原理图（及 PCB/BOM/GPIO/指南）双链，填写板型、硬件版本、平台/芯片/模组；
2. 摘要说明文档定位：开发板参考电路，非量产强制标准；
3. 记录核心电路章节、关键元件/网络/图纸页码索引；
4. YAML 元数据完整填充：`board_model`、`hardware_version`、`platform_family`、`chip_model`、`module_model`、`sources`、`tags: ["开发板","板卡系列-XX","型号-XX","原始资料"]`；
5. 双向关联板卡实体页、对应 MCU 芯片实体页。

### 步骤4：新建开发板实体页 wiki/dev_board/all/board_entity/
使用 `_template.md`（type: dev_board）新建页面，逐项填写 11 项核心参数：
1. 平台/芯片/模组/上芯方式 → 双链至 `wiki/mcu/all/chip_entity/`；
2. 存储/供电/外设/调试/适用场景 → 引用对应 `peripheral/`、`design_rules/`；
3. 使用指南文档、图纸 → 双链 raw 与 `schematics/` 提取页；
4. 所有参数标注来源（原理图页码/坐标/图号）；模糊处标记「待人工核实」。

### 步骤5：新建图纸提取页 wiki/dev_board/all/schematics/
使用 `_template.md`（type: dev_board_sch）新建页面，沉淀电源树/复位/时钟/BOOT/调试/存储/外设关键位号参数、GPIO 分配表、BOM 关键器件，全部标注溯源。

### 步骤6：更新全局导航与变更日志
1. 修改 `index_DEVBOARD_ALL.md`，在「已入库开发板」段登记本板，链接实体页、来源页、图纸提取页与对应 MCU；
2. 在 `log_DEVBOARD_ALL.md` 尾部追加操作记录，固定格式：
`YYYY-MM-DD | 导入资料：开发板原理图raw完整路径（+PCB/BOM/GPIO/指南） | 新建页面：页面清单 | 更新页面：页面清单 | 待人工确认：开发板方案与量产规范冲突明细`

### 步骤7：双链闭环自检
校验所有新建页面双向关联双链，无断链、无效链接；确认与 MCU 知识库平台/芯片双链可达。

## 四、强制执行规则
1. Raw 层开发板资料（`raw/dev_board/` 下）仅读取解析，禁止修改、移动、删除原始文件；
2. 所有电路、参数、网络必须标注来源（原理图页码/坐标/图号）；描述模糊、缺少量化指标统一标记「待人工核实」并暂停，禁止自行编造硬件参数；
3. 开发板电路与企业硬件设计指南、芯片手册存在冲突时，全部保留，明确区分优先级：芯片 datasheet / 用户手册 > 企业硬件设计指南 > 开发板演示电路；
4. 原有 Wiki 页面仅增量补充，不删除、覆盖历史规范，不修改 MCU 侧任何文件（仅作单向双链引用）；
5. 所有页面必须使用对应分类 `_template.md` 标准模板，YAML 元数据必填字段完整；
6. 不生成网表、不做电气仿真、不解析电路走线/焊盘（遵循 EDA 提取规范，仅提取文字标注）。

## 五、执行完成后输出自检汇报清单
操作结束后输出以下复核信息：
1. 本次新建全部 Wiki 页面完整路径（sources / board_entity / schematics）；
2. 本次更新的原有 Wiki 页面路径清单（index_DEVBOARD_ALL / log_DEVBOARD_ALL）；
3. 识别出的开发板电路与既有量产规范冲突明细；
4. 本板 11 项核心参数填写完整度核对；
5. `index_DEVBOARD_ALL.md`、`log_DEVBOARD_ALL.md` 更新完成确认；
6. 全页面双链完整性自检结论（含与 MCU 知识库平台/芯片双链可达性）。
