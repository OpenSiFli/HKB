# MCU最小系统原理图版本增量更新入库指令提示词

## 前置约束
1. 当前 Obsidian Vault 已搭建企业全系列 MCU 硬件知识库，根目录 `AGENTS_MCU_ALL.md` 为最高运维规范，全部操作严格遵循该文件条款；
2. 本型号 MCU 历史最小系统原理图已完成结构化入库，`wiki/mcu/all/sources/` 已存在该最小系统来源页，`wiki/mcu/all/chip_entity/` 存在芯片实体页面，配套外设页、设计规范、故障案例、审图规则完整；
3. 本次为**同一款 MCU 迭代新版最小系统原理图**，不是全新导入，核心逻辑为新旧对比、增量更新、多版本数据共存；
4. 待处理文件路径：【替换为新版最小系统原理图 raw 完整路径，示例：raw/mcu/ref_design/min_sys_sch/SF32LB52X_MinSys_Sch_V2.0.pdf】
文档类型：MCU 新版最小系统原理图（EDA 工具导出的 PDF，覆盖电源树/复位/时钟晶振/外置存储（QSPI NOR Flash / SPI NAND / SDRAM / eMMC 等 boot 与扩展存储接口）/BOOT/调试接口/去耦/滤波/ESD 防护，以及 BOM 关键器件 AVL 物料选型与合格供应商的完整参考电路与 BOM）

## 一、核心任务目标
1. 完整比对旧版知识库最小系统信息与新版原理图，识别新增、修改、作废、冲突的电路/参数内容；
2. 新建新版原理图来源归档页，所有 Wiki 页面仅增量补充，**禁止覆盖、删除旧版历史信息**，冲突参数分版本标注来源、适用原理图版本；
3. 同步更新芯片实体、外设规范、设计规范、故障案例、原理图 AI 审图校验规则；
4. 更新全局导航索引与知识库变更日志，完善双链关联；
5. 最终知识库可区分不同最小系统版本对应的硬件设计要求，同时支撑全文检索、原理图自动审图、故障分析、评审报告自动输出。

## 二、全模块新旧对比提取范围
### 1. 最小系统电路模块对比（映射至 chip_entity 与 peripheral）
- 电源树（BUCK/LDO/各电源域/去耦）→ 比对 `peripheral/SF32LB52X_Peripheral_Power.md` 与 `design_rules/DR_PowerArchitecture.md`、`check_rules/CR_PowerDomains.md`；
- 复位电路（POR/BOR/nRST 外接电阻/电容变更）→ 比对 `chip_entity` §复位系统 与 `check_rules/CR_Reset_Levels.md`；
- 时钟/晶振（48M 主晶振 + 32.768k RTC + 负载电容取值调整）→ 比对 `peripheral/SF32LB52X_Peripheral_Clock.md` 与 `check_rules/CR_XTAL48M.md`；
- BOOT 配置（strapping 电阻/跳线/电平变更）→ 比对 `design_rules/DR_BootMode.md` 与 `check_rules/CR_BootMode_Register.md`；
- 下载调试接口（SWD/UART 引脚、测试点、上拉调整）→ 比对 `peripheral/SF32LB52X_Peripheral_USB.md` 与 `design_rules/DR_Debug_Interface.md`；
- 外置存储（QSPI NOR Flash / SPI NAND / SDRAM / eMMC 等 boot 与扩展存储接口，MPI/SDMMC 引脚互斥调整）→ 比对 `peripheral/SF32LB52X_Peripheral_Memory.md` 与 `check_rules/CR_SDMMC_MPI2_Exclusive.md`；
- AVL 物料（BOM 关键器件选型、合格供应商、替代料变更）→ 关联 `raw/mcu/vendor/device_spec/` AVL 入库，比对关键元器件选型与供应商约束；
- 去耦/滤波/ESD 防护 → 比对对应 `design_rules` / `check_rules`。

### 2. 元件与网络变更（更新 peripheral / fault_case）
1. 位号、参数（阻值/容值/型号/耐压）、网络标号、引脚映射的新增与调整；
2. 已知失效整改：旧版存在、新版已修复的电路坑点，或新版新增限制；
3. 区分：旧版参考设计演示项、新版量产强制标准项。

### 3. 原理图 AI 自动审图校验规则（更新 check_rules 库）
针对所有变更后的强制硬件约束，新增/修订校验规则；
原有冲突规则完整保留，增加版本标签，区分「旧版原理图标准」「新版原理图标准」；
每条规则统一包含：判定条件、违规现象、风险等级、分版本整改方案、原理图页码溯源。

### 4. 设计规范与故障案例（更新 design_rules / fault_case 库）
1. 新版新增/修改的必选电路、推荐器件参数、去耦/负载电容取值、BOOT 上拉下拉、调试接口保留焊盘；
2. 新版新增硬件风险、勘误、废弃危险电路，录入 `fault_case/`，标注适用原理图版本。

## 三、标准化分步执行流程（顺序不可打乱）
### 步骤1：检索历史知识库，建立对比基准
1. 查询 `wiki/mcu/all/sources/`，调取该 MCU 所有历史最小系统来源页，记录旧版本参数与引用页码；
2. 打开 `wiki/mcu/all/chip_entity/` 对应芯片实体页面，读取「最小系统参考电路」板块作为比对基准；
3. 预加载该芯片全部外设页、设计规范、校验规则、故障案例页面，用于逐项对比更新。

### 步骤2：EDA 原理图 PDF 文本提取
依 `EDA原理图PDF识别提示词.md` 生成新版结构化 JSON（方案A 优先，失效切 OCR），保留页码/坐标用于溯源，禁止脑补虚构电路。

### 步骤3：创建新版最小系统原理图来源索引页
在 `wiki/mcu/all/sources/` 使用 `_template.md` 来源模板新建页面：
1. 绑定 raw 新版原理图双链，填写新版本号、发布日期、适配 MCU 系列/型号、硬件版本；
2. 摘要写明本次最小系统核心电路变更范围，记录关键变更元件/网络页码索引；
3. YAML 元数据完整填充 `mcu_family`、`mcu_model`、`hardware_version`、`sources`、`tags: ["最小系统原理图","参考设计","ref_design"]`；
4. 双向关联旧版最小系统来源页、芯片实体主页面。

### 步骤4：增量更新芯片实体页面
1. 逐项比对新旧最小系统信息，分为三类：新增内容、内容变更、新旧参数冲突；
2. 冲突数据并行留存两套完整说明，分别标注对应原理图版本、生效场景，绝不删除旧描述；
3. 仅补充新版新增约束，无变化内容不重复冗余写入；
4. 所有变更条目标注溯源：新版原理图 + 对应页码；
5. 完善双链，关联同步更新后的外设、校验规则、故障案例页面。

### 步骤5：批量增量更新外设专项页面
遍历该芯片相关外设页面（电源/时钟/外置存储(MPI/SDMMC)/GPIO/USB(调试) 等）：
1. 补充新版原理图带来的电路参数调整、新增限制、位号/网络要求；
2. 将新版原理图添加为本页面来源引用；
3. 新旧冲突外设约束分版本标注，清晰区分适用原理图版本；
明确区分「参考设计演示」与「量产强制标准」。

### 步骤6：新增/修订原理图审图校验规则
1. 对新增、修改的硬性电路要求，生成全新校验规则；
2. 历史冲突规则保留不动，增加版本适用标签；
3. 统一规则模板字段，适配 PDF 原理图 AI 自动解析校验。

### 步骤7：同步更新设计规范库、故障案例库
1. 新版勘误、新增硬件风险录入 `fault_case/`，标注适用原理图版本；
2. 电源/晶振/BOOT/调试相关更新补充至 `design_rules/`。

### 步骤8：更新全局导航与变更日志
1. 修改 `index_MCU_ALL.md`，在对应芯片型号分类或「参考设计」分类下补充新版最小系统原理图来源页入口链接；
2. 在 `log_MCU_ALL.md` 尾部追加操作记录，严格使用固定格式：
`YYYY-MM-DD | 更新资料：新版最小系统原理图raw路径 | 新建页面：页面清单 | 更新页面：页面清单 | 待人工确认：最小系统电路与量产规范冲突明细`

### 步骤9：双链闭环自检
遍历本次所有新建、修改页面，校验全部双向关联双链，清除无效断链。

## 四、强制不可违反规则（对齐 AGENTS_MCU_ALL.md）
1. Raw 层新版最小系统原理图仅读取解析，禁止修改、移动、删除原始 PDF，历史旧版 raw 文件永久封存；
2. 所有新增、变更电路参数、网络必须标注来源（新版原理图 + 页码）；描述模糊、参数缺失内容统一标记「待人工核实」并暂停，禁止自行编造硬件参数；
3. 新旧原理图存在参数冲突时，严禁覆盖旧内容，必须分版本完整留存两套标准，标注适用范围；
4. 所有原有 Wiki 页面仅做增量补充，不删除任何历史文字、规则、案例，不得修改其他无关 MCU 型号知识库；
5. 内容模糊、缺少明确硬件约束无法提炼规则时，立即停止执行并向我提问，禁止自行编造电路参数；
6. 所有页面强制使用对应分类下 `_template.md` 标准模板，YAML 必填元数据不得缺省；
7. 不生成网表、不做电气仿真、不解析电路走线/焊盘（遵循 EDA 提取规范，仅提取文字标注）。
