# 调用指令参考提示词（知识库入库总调度）

> 本文件是硬件知识库入库的**总调度入口**。当你在 AI 输入框输入「新增 xxx文件」「更新 xxx文件」（或「导入 / 入库 / 补充 / 升级 / 迭代」等等价表达）时，AI 会按本文件的「调度协议」与「路由表」自动定位对应的 `cmd/` 指令文件，把源文件放入对应 raw 目录，并按指令执行入库 / 更新，最后输出自检报告。
>
> 本文件覆盖知识库全部 **18 条**入库指令：MCU 类 14 条（7 新增 + 7 更新）+ 最小系统原理图 2 条 + 开发板独立大类 2 条。

## 〇、如何被调用（AI 行为约定）

当你（用户）在输入框输入：

- `新增 <文件路径或文件名>` → 触发**新增**流程
- `更新 <文件路径或文件名>` → 触发**更新（增量多版本）**流程
- 等价表达：`导入 / 入库 / 补充 / 建立` ≈ 新增；`升级 / 迭代 / 新版 / 改版 / 修订 / 增量` ≈ 更新

AI 自动执行：

1. 解析**动作**（新增 / 更新）与**文件类型**关键词；
2. 查「二、路由表」匹配指令文件 `cmd/xxx.md`；
3. 读取该指令文件，取得路径占位符与推荐 raw 位置；
4. 定位 / 归置源文件（见调度协议步骤 3）；
5. 严格按指令步骤 + `AGENTS_MCU_ALL.md`（MCU 类）或 `wiki/dev_board/` 模板（开发板类）执行；
6. 输出指令末尾的自检清单。

## 一、调度协议（核心执行流程）

1. **解析意图**
   - 动作：含「新增 / 新建 / 导入 / 入库 / 补充」→ 新增；含「更新 / 升级 / 迭代 / 新版 / 改版 / 修订 / 增量」→ 更新。
   - 文件类型：从文件名 / 内容提取关键词，对照「二、路由表」匹配指令文件。无法判定时，向用户确认是哪种资料。
   - 源文件路径：用户已给完整 / 相对路径则直接使用；仅给文件名则进入步骤 3。

2. **加载指令**：读取匹配到的 `cmd/<对应指令文件>`，获取其「待导入 / 待处理文件路径」占位符、`【推荐 raw 位置】`、执行步骤与自检清单。

3. **归置源文件（Raw 存放）**
   - 若源文件已位于该指令的「推荐 raw 位置」（或用户显式给出的 raw 路径），直接读取（Raw 只读：只读取，不修改、不删除源文件）。
   - 若源文件在别处（如用户桌面 / 下载 / 临时目录），将其**复制**（非移动）到「推荐 raw 位置」后再读取，保留原文件不动。
   - 若按文件名找不到文件，列出可能的「推荐 raw 位置」并请用户提供实际路径。

4. **执行入库**：严格按指令步骤执行。MCU 类写入 `wiki/mcu/all/` 并同步 `index_MCU_ALL.md` / `log_MCU_ALL.md`；开发板类写入 `wiki/dev_board/all/` 并同步 `index_DEVBOARD_ALL.md` / `log_DEVBOARD_ALL.md`；原理图类（最小系统 / 开发板）先调用 `EDA原理图PDF识别提示词.md` 做 PDF 矢量提取。

5. **输出自检**：按指令末尾「自检清单」输出汇报（新建页 / 更新页 / 冲突待核实 / 新增规则数 / 索引+日志确认 / 双链完整性）。

6. **不编造**：任何模糊、缺失、无法从源文件核实的参数，一律标注「待人工核实」，不臆造；更新类遇冲突分版本留存，不覆盖历史。
