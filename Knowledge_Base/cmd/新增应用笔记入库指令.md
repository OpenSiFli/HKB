# MCU应用笔记导入知识库全流程入库指令提示词
## 前置约束
1. 当前Obsidian Vault已搭建企业全系列MCU硬件知识库，根目录`AGENTS_MCU_ALL.md`为最高运维规范，所有操作严格遵守该文件全部条款；
2. 待导入文件路径：【替换应用笔记完整raw路径，示例：raw/mcu/ref_design/app_note/AN001_MCU低功耗硬件设计应用笔记V1.0.pdf】
3. 文档类型：MCU原厂/企业内部硬件应用笔记，包含专项电路方案、外设实操设计、优化方案、EMC整改、低功耗设计、故障优化、多器件搭配电路、实测数据、勘误规避方案
4. 文档定位：专项场景硬件参考方案，用于研发设计参考、图纸优化建议、故障整改、原理图AI审图优化项判定，优先级：企业硬件设计指南 > 芯片手册 > 应用笔记。

## 一、核心任务目标
1. 完整拆解应用笔记内全部硬件相关内容，按场景、外设、芯片型号结构化归档至对应Wiki模块；
2. 提取笔记中成熟参考电路、优化约束、器件选型方案，补充至外设库、芯片实体库、通用设计规范库；
3. 基于笔记中的禁止电路、优化要点生成原理图审图**优化类校验规则**，用于图纸评审输出改进建议；
4. 笔记内故障解决、硬件优化方案归档至故障案例库，支撑问题检索与报告生成；
5. 新建来源索引页，搭建芯片、外设、专项主题双向双链，更新全局导航与变更日志；
6. 应用笔记方案与企业标准、芯片手册冲突时，多版本内容并行留存，明确区分“强制规范”与“可选优化方案”。

## 二、全维度提取拆解范围
### 1. 适用芯片与场景基础信息（关联chip_entity芯片实体页）
1. 笔记适配MCU系列、具体型号、硬件版本；
2. 适用业务场景：低功耗、高速通信、电机驱动、模拟采集、静电防护、量产成本优化等；
3. 配套硬件基础条件：供电范围、外设资源、PCB层数要求、温度适用区间。

### 2. 专项外设完整硬件方案（更新peripheral外设库）
覆盖笔记涉及的GPIO、ADC、SPI、I2C、CAN、TIM、电源模块等外设：
1. 最优外围器件参数、滤波/匹配/限流电阻容值选型；
2. 特殊布线约束、阻抗匹配、地分割优化方案；
3. 多外设共存干扰抑制硬件电路；
4. 区分通用方案、仅特定MCU型号适配方案。

### 3. 电源、时钟、复位、EMC/安规优化设计（补充design_rules）
1. 多电源域降噪电路、多级滤波方案、低功耗切换硬件设计；
2. 晶振起振稳定性优化、外部参考电压降噪电路；
3. ESD、浪涌、辐射干扰配套防护改进方案；
4. 量产测试验证通过的标准整改电路。

### 4. 原理图审图优化类校验规则（补充check_rules校验库）
提取笔记中不强制但可大幅提升可靠性/EMC/功耗表现的设计要点，生成优化建议规则：
每条规则标记风险等级为「优化建议」，不做强制拦截，仅在评审报告输出改进方案；
同时记录笔记中明确禁止、易引发隐性故障的电路，标记为「一般/严重风险」。

### 5. 硬件问题、隐性故障整改方案（更新fault_case故障库）
1. 笔记记录的硬件隐性问题：通信丢包、功耗偏高、低温工作异常、干扰死机等；
2. 根因分析、配套整改硬件电路、长期规避设计方案；
3. 同类图纸快速拦截校验逻辑。

### 6. 评审报告标准化优化话术（补充report_template）
提取专项场景优化描述、可靠性提升说明、整改标准段落，用于原理图评审报告自动输出改进建议。

## 三、标准执行步骤（顺序不可打乱）
### 步骤1：全库预检索查重
1. 检索`wiki/mcu/all/sources/`，确认本应用笔记是否已归档，避免重复创建来源页；
2. 检索笔记适配MCU型号芯片实体页、对应外设页面、设计规范、故障案例页面，建立对比基准。

### 步骤2：创建应用笔记来源索引页 wiki/mcu/all/sources/
使用`_template.md`来源模板新建页面：
1. 绑定raw应用笔记双链链接，填写笔记编号、版本、发布日期、适配MCU型号、应用场景；
2. 摘要概括笔记核心硬件优化方案，记录关键电路、校验规则对应页码；
3. YAML元数据完整填充：`mcu_family`、`mcu_model`、`sources`、`tags: ["应用笔记","AN文档","硬件优化","低功耗/EMC/模拟采集"]`；
4. 双向关联对应MCU芯片实体页、相关外设总页面。

### 步骤3：更新对应MCU芯片实体页面 wiki/mcu/all/chip_entity/
1. 在芯片实体页新增「配套应用笔记专项方案」板块，记录本笔记适配场景与核心硬件要点；
2. 建立双向双链关联应用笔记来源页。

### 步骤4：批量更新涉及外设专项页面 wiki/mcu/all/peripheral/
1. 对笔记覆盖的每一类外设，补充笔记提供的优化电路、器件选型、布线约束；
2. 将本应用笔记添加为页面来源引用；
3. 标注该方案适用MCU型号范围，区分通用优化与专属适配方案。

### 步骤5：新增原理图优化类校验规则 wiki/mcu/all/check_rules/
1. 笔记中禁止电路生成风险校验规则，优化方案生成「优化建议」类规则；
2. 每条规则完整包含判定条件、现象、优化方案、依据（应用笔记+页码）；
3. 统一备注：本规则为应用笔记优化方案，优先级低于企业硬件强制设计指南。

### 步骤6：更新设计规范库、故障案例库、报告模板库
1. 通用硬件优化方案补充至`wiki/mcu/all/design_rules/`专项场景子页面；
2. 隐性故障、整改方案存入`fault_case/`，绑定对应MCU型号；
3. 场景化优化文案补充至`report_template/`。

### 步骤7：更新全局导航与变更日志
1. 修改`index_MCU_ALL.md`，新增「MCU应用笔记专项方案」分类入口，链接本笔记来源页；
2. 在`log_MCU_ALL.md`尾部追加操作记录，固定格式：
`YYYY-MM-DD | 导入资料：应用笔记raw完整路径 | 新建页面：页面清单 | 更新页面：页面清单 | 待人工确认：笔记方案与企业规范冲突明细`

### 步骤8：双链闭环自检
校验所有新建、修改页面双向关联双链，无断链、无效链接。

## 四、强制执行规则（对齐AGENTS_MCU_ALL.md）
1. Raw层应用笔记仅读取解析，禁止修改、移动、删除原始PDF；
2. 所有优化电路、选型参数、约束条件必须标注来源（应用笔记+页码）；描述模糊、无量化指标统一标记「待人工核实」；
3. 应用笔记方案与企业硬件设计指南、芯片datasheet存在冲突时，两套内容全部留存，明确优先级：企业强制规范 > 芯片手册 > 应用笔记优化方案；
4. 原有Wiki页面仅增量补充优化参考内容，不删除、覆盖历史规范，不修改无关MCU型号知识；
5. 笔记描述模糊、无明确可落地硬件电路标准，无法提炼校验规则时，立刻暂停执行并向我提问，禁止自行编造硬件参数；
6. 所有页面必须使用对应分类`_template.md`标准模板，YAML元数据必填字段完整；
7. 软件配置、代码例程仅简要记录，核心重点处理硬件电路、器件选型、PCB优化、故障整改、原理图评审优化规则。
