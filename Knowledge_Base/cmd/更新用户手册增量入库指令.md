# MCU用户手册版本增量更新入库指令提示词
## 前置约束
1. 当前Obsidian Vault已搭建企业全系列MCU硬件知识库，根目录`AGENTS_MCU_ALL.md`为最高运维规范，全部操作严格遵循该文件条款；
2. 本型号MCU历史用户手册、规格书已完成结构化入库，`wiki/mcu/all/chip_entity/`存在该芯片实体页面，配套来源页、外设页、校验规则、故障案例完整；
3. 本次为**同一款MCU迭代新版用户手册**，不是全新芯片导入，核心逻辑为新旧对比、增量更新、多版本数据共存；
4. 待处理文件路径：【替换为新版用户手册raw完整路径，示例：raw/mcu/all_chip/datasheets/XX32L07x_User_Manual_V3.0.pdf】
文档类型：MCU新版用户手册（含硬件电路、外设、PCB、勘误、应用方案、调试说明）

## 一、核心任务目标
1. 完整比对旧版知识库信息与新版用户手册，识别新增、修改、作废、冲突的硬件相关内容；
2. 新建新版手册来源归档页，所有Wiki页面仅增量补充，**禁止覆盖、删除旧版历史信息**，冲突参数分版本标注来源、适用手册版本；
3. 同步更新芯片实体、外设规范、设计规则、故障案例、原理图AI审图校验规则、报告模板；
4. 更新全局导航索引与知识库变更日志，完善双链关联；
5. 最终知识库可区分不同手册版本对应的硬件设计要求，同时支撑全文检索、原理图自动审图、故障分析、评审报告自动输出。

## 二、全模块新旧对比提取范围
### 1. 芯片基础硬件信息（更新chip_entity芯片实体页）
- 封装、引脚定义、引脚复用功能、禁止悬空引脚变更；
- 极限电气参数、推荐供电、IO驱动能力、工作温度、功耗指标调整；
- Flash/RAM资源、内核主频、电源域划分、上电/掉电时序更新；
- 最小系统相关变更：复位、晶振、BOOT引脚、下载调试接口硬件约束。

### 2. 全外设硬件电路规范（增量更新peripheral外设库）
遍历手册全部外设（GPIO/ADC/DAC/UART/SPI/I2C/CAN/TIM/PWM/DMA等），对比提取变更项：
外设推荐外围器件参数、上下拉/滤波/限流电阻范围、负载上限、引脚复用冲突限制、高低压兼容条件、低功耗硬件改造要求；
所有变更内容标注仅适用于当前新版用户手册。

### 3. 通用硬件&PCB设计规范（更新design_rules库）
新版新增/修改的电源分割、模拟地数字地处理、晶振布线、差分阻抗、ESD/浪涌/安规、EMC防护电路、量产焊接上电要求。

### 4. 硬件勘误、缺陷、失效案例（更新fault_case故障库）
1. 新版手册新增硬件BUG、勘误修正、废弃危险电路；
2. 补充易烧毁/锁死的错误接线、失效复现条件、新版专属规避方案；
3. 区分：旧版存在但新版已修复缺陷、新版新增硬件限制。

### 5. 原理图AI自动审图校验规则（更新check_rules库）
针对所有变更后的强制硬件约束，新增/修订校验规则；
原有冲突规则完整保留，增加版本标签，区分“旧手册标准”“新版手册标准”；
每条规则统一包含：判定条件、违规现象、风险等级、分版本整改方案、手册页码溯源。

### 6. 报告标准化话术补充（更新report_template库）
提取新版手册对应的合规判定描述、风险说明、整改标准段落，用于自动生成原理图评审、硬件故障分析报告。

## 三、标准化分步执行流程（顺序不可打乱）
### 步骤1：检索历史知识库，建立对比基准
1. 查询`wiki/mcu/all/sources/`，调取该MCU所有历史用户手册、规格书来源页，记录旧版本参数与引用页码；
2. 打开`wiki/mcu/all/chip_entity/`对应芯片实体页面，读取完整历史硬件信息作为比对基准；
3. 预加载该芯片全部外设页面、校验规则、故障案例页面，用于逐项对比更新。

### 步骤2：创建新版用户手册来源索引页
在`wiki/mcu/all/sources/`使用`_template.md`来源模板新建页面：
1. 绑定raw新版手册双链链接，填写手册新版本号、发布日期、适配MCU系列/型号、硬件版本；
2. 摘要写明本次手册核心硬件变更范围，记录关键变更章节页码；
3. YAML元数据完整填充`mcu_family`、`mcu_model`、`hardware_version`、`sources`、`tags`；
4. 双向关联旧版手册来源页、芯片实体主页面。

### 步骤3：增量更新芯片实体页面
1. 逐项比对新旧硬件信息，分为三类：新增内容、内容变更、新旧参数冲突；
2. 冲突数据并行留存两套完整说明，分别标注对应手册版本、生效场景，绝不删除旧描述；
3. 仅补充新版新增约束，无变化内容不重复冗余写入；
4. 所有变更条目标注溯源：新版用户手册+对应页码；
5. 完善双链，关联同步更新后的外设、校验规则、故障案例页面。

### 步骤4：批量增量更新外设专项页面
遍历该芯片支持的所有外设页面：
1. 补充新版手册带来的外设硬件参数调整、新增限制、电路要求；
2. 将新版手册添加为本页面来源引用；
3. 新旧冲突外设约束分版本标注，清晰区分适用手册版本。

### 步骤5：新增/修订原理图审图校验规则
1. 对新增、修改的硬性硬件要求，生成全新校验规则；
2. 历史冲突规则保留不动，增加版本适用标签；
3. 统一规则模板字段，适配PDF原理图AI自动解析校验。

### 步骤6：同步更新设计规范库、故障案例库、报告模板库
1. 新版勘误、新增硬件风险录入`fault_case/`，标注适用手册版本；
2. PCB、EMC、电源相关更新补充至`design_rules/`；
3. 新增合规判定、整改文案补充至`report_template/`。

### 步骤7：更新全局导航与变更日志
1. 修改`index_MCU_ALL.md`，在对应芯片型号分类下补充新版手册来源页入口链接；
2. 在`log_MCU_ALL.md`尾部追加操作记录，严格使用固定格式：
`YYYY-MM-DD | 更新资料：新版用户手册raw路径 | 新建页面：页面清单 | 更新页面：页面清单 | 待人工确认：参数冲突/模糊内容明细`

### 步骤8：双链闭环自检
遍历本次所有新建、修改页面，校验全部双向关联双链，清除无效断链。

## 四、强制不可违反规则（对齐AGENTS_MCU_ALL.md）
1. Raw层新版用户手册仅读取解析，禁止修改、移动、删除原始PDF，历史旧版raw文件永久封存；
2. 所有新增、变更硬件参数、电路要求必须标注来源（新版手册+页码）；描述模糊、参数缺失内容统一标记「待人工核实」；
3. 新旧手册存在参数冲突时，严禁覆盖旧内容，必须分版本完整留存两套标准，标注适用范围；
4. 所有原有Wiki页面仅做增量补充，不删除任何历史文字、规则、案例，不得修改其他无关MCU型号知识库；
5. 手册内容模糊、缺少明确硬件约束无法提炼规则时，立即停止执行并向我提问，禁止自行编造硬件参数；
6. 所有页面强制使用对应分类下`_template.md`标准模板，YAML必填元数据不得缺省；
7. 软件纯寄存器、代码示例仅简要记录，核心重点处理硬件电气、电路、PCB、原理图校验相关内容。

## 五、执行完成后输出完整自检汇报清单
全部操作结束后，输出以下复核信息：
1. 本次新建的全部Wiki页面完整路径；
2. 本次增量更新的原有Wiki页面完整路径；
3. 新旧手册比对识别出的全部参数冲突、待核实内容明细；
4. 本次新增/修订原理图审图校验规则总数量；
5. `index_MCU_ALL.md`、`log_MCU_ALL.md`更新完成确认；
6. 全页面双链完整性自检结论。
