# MCU硬件设计指南新版本增量对比更新入库指令提示词
## 前置基础约束
1. 当前Obsidian Vault已搭建企业全系列MCU硬件知识库，根目录`AGENTS_MCU_ALL.md`为最高运维规范，所有操作必须严格执行该文件全部规则；
2. 历史版本硬件设计指南已完成结构化入库，`wiki/mcu/all/sources/`存在旧版指南来源页，`wiki/mcu/all/design_rules/`、`wiki/mcu/all/check_rules/`已存在全套通用硬件规范；
3. 本文档为**企业顶层MCU硬件设计指南迭代新版本**，优先级高于所有MCU芯片datasheet、用户手册；新旧标准冲突时需明确标注优先级差异；
4. 待处理新版文件路径：【替换为新版硬件设计指南raw完整路径，示例：raw/mcu/company_spec/hardware/MCU通用硬件设计指南V4.0.pdf】
文档类型：新版企业MCU硬件强制设计规范指南

## 一、核心任务目标
1. 全量对比旧版知识库内所有通用硬件规范，识别新版指南中新增、修改、废止、存在参数冲突的硬件设计要求；
2. 新建新版指南来源归档页，所有Wiki页面仅增量补充内容，**严禁覆盖、删除旧版历史规范**，新旧冲突条款并行留存并标注版本、优先级；
3. 同步更新通用设计规范、外设电路标准、PCB/EMC/安规要求、原理图&PCB自动校验规则、故障案例、评审报告标准话术；
4. 更新全局知识导航索引与知识库变更日志，完善全模块双向双链关联；
5. 知识库可区分新旧两版设计标准，AI审图、知识检索、报告生成时可区分适用版本规范。

## 二、全模块新旧对比提取更新范围
### 1. 全系通用最小系统设计规范（更新design_rules、chip_entity关联内容）
对比识别供电回路、电源退耦、复位电路、晶振参数、BOOT配置、下载调试接口、多电源域隔离、上电时序的新增/变更强制标准；
区分通用标准、特定MCU系列差异化约束。

### 2. 全外设标准化硬件电路规范（批量增量更新peripheral外设库）
遍历GPIO、ADC、UART、SPI、I2C、CAN、TIM/PWM等全部外设：
更新企业统一上下拉电阻、滤波/限流器件规格、引脚复用布线限制、总线匹配、高低压防护、低功耗硬件改造要求；
旧版规范保留，新版变更内容单独补充并标注生效版本。

### 3. PCB、接地、EMC、ESD、安规强制规范（design_rules核心更新）
更新模拟/数字地分割、单点接地、功率地处理、晶振/高速信号布局走线约束、防护器件摆放规范、高低压隔离间距、保险丝选型、多层板电源分割要求；
新增/修订EMC整改通用方案、量产硬件防护标准。

### 4. 原理图&PCB统一审图校验规则（增量更新check_rules校验库）
提取新版新增/调整的图纸强制检查项，生成新校验规则；旧版冲突规则完整保留，增加版本标签区分；
所有规则统一标记【企业顶层硬件设计指南Vx.x强制规范，优先级高于芯片手册】，AI审图优先执行本套规则。

### 5. 硬件典型错误、量产风险案例（更新fault_case故障库）
新版新增设计缺陷、易烧毁电路、EMC失效场景、废止的老旧方案、新版专属硬件规避措施；
标注对应生效指南版本，区分旧版允许、新版禁止的电路方案。

### 6. 评审报告标准化文案（更新report_template报告库）
同步更新风险分级定义、问题标准描述、合规判定、整改结论话术，适配新版设计规范的评审输出要求。

## 三、标准化分步执行流程（顺序不可调整）
### 步骤1：检索历史知识库，建立对比基准
1. 检索`wiki/mcu/all/sources/`，调取旧版硬件设计指南来源页，记录旧版版本、规范条款、引用页码；
2. 读取`wiki/mcu/all/design_rules/`、`wiki/mcu/all/check_rules/`全套历史通用规范作为比对基准；
3. 预加载全部外设、芯片实体页面，准备批量增量更新。

### 步骤2：创建新版硬件设计指南来源索引页
在`wiki/mcu/all/sources/`使用`_template.md`来源模板新建页面：
1. 绑定raw新版指南双链链接，填写新版本号、发布生效日期、适用范围（企业全系MCU）；
2. 摘要写明本次指南核心变更板块，记录关键变更章节页码；
3. YAML元数据完整填充`mcu_family: ["全系通用"]`、`sources`、`tags: ["硬件设计指南","企业强制顶层规范","原理图审图标准"]`；
4. 双向关联旧版指南来源页、design_rules总页面、check_rules总页面。

### 步骤3：增量更新通用硬件设计规范库 wiki/mcu/all/design_rules/
1. 打开通用硬件规范总页面，逐项比对新旧条款，分为三类：新增内容、内容变更、新旧冲突；
2. 冲突内容并行完整留存两套标准，标注各自适用指南版本，明确优先级：新版指南 > 旧版指南 > 芯片原厂手册；
3. 所有变更条目溯源标注：新版硬件设计指南+对应页码；
4. 同步更新分模块电源、时钟、接地、EMC、安规子页面。

### 步骤4：批量增量更新所有外设专项页面 wiki/mcu/all/peripheral/
1. 为每一类外设页面补充新版指南带来的标准化电路调整、新增约束；
2. 将新版指南添加为本页面来源引用；
3. 新旧外设规范冲突内容分版本标注，区分生效指南版本。

### 步骤5：新增/修订原理图、PCB自动校验规则 wiki/mcu/all/check_rules/
1. 针对新增、修改的强制设计要求生成全新校验规则；
2. 旧版冲突校验规则完整保留，增加版本标签区分适用场景；
3. 每条规则固定包含：判定条件、违规现象、风险等级、分版本整改方案、规范依据来源。

### 步骤6：同步更新故障案例库、报告模板库
1. 新版新增硬件风险、废弃电路方案录入`fault_case/`，绑定对应新版校验规则；
2. 适配新版规范的评审话术、风险说明补充至`report_template/`。

### 步骤7：更新全局导航与变更日志
1. 修改`index_MCU_ALL.md`顶层导航，补充新版硬件设计指南来源页入口链接；
2. 在`log_MCU_ALL.md`尾部追加操作记录，固定格式：
`YYYY-MM-DD | 更新资料：新版硬件设计指南raw完整路径 | 新建页面：页面路径清单 | 更新页面：页面路径清单 | 待人工确认：新旧规范冲突明细`

### 步骤8：双链闭环自检
遍历本次所有新建、修改页面，校验全部双向关联双链，清理无效断链。

## 四、不可违反的强制约束（对齐AGENTS_MCU_ALL.md）
1. Raw层新版硬件设计指南仅读取解析，禁止修改、移动、删除原始PDF，旧版指南原始文件永久封存不改动；
2. 所有新增、变更规范条款必须标注来源（新版指南+页码）；描述模糊、无量化指标、边界不清晰内容统一标记「待人工核实」；
3. 新旧指南、指南与芯片手册参数冲突时，严禁直接覆盖旧内容，多版本内容全部留存，清晰标注优先级与适用版本；
4. 原有Wiki页面仅增量补充内容，不删除任何历史规范、规则、案例，不修改各MCU型号专属私有知识；
5. 指南描述模糊、无明确可落地硬件标准，无法提炼校验规则时，立即停止执行并向我提问，禁止自行编造设计参数；
6. 所有页面强制使用对应分类`_template.md`标准模板，YAML元数据必填字段完整，不得缺省；
7. 软件相关内容仅简要记录，核心工作聚焦硬件电路、PCB布局布线、原理图审图、EMC安规规范。
