# MCU最小系统原理图结构化入库与 Wiki 生成指令提示词

## 前置约束
1. 当前 Obsidian Vault 已搭建企业全系列 MCU 硬件知识库，根目录 `AGENTS_MCU_ALL.md` 为最高运维规范，所有操作严格遵守该文件全部条款；
2. 待导入文件路径：【替换为最小系统原理图完整 raw 路径，示例：raw/mcu/ref_design/min_sys_sch/SF32LB52X_MinSys_Sch_V1.0.pdf】
3. 文档类型：MCU 最小系统原理图（EDA 工具导出的 PDF），覆盖最小系统必需的电源树（BUCK/LDO/去耦）、复位、时钟与晶振（48M 主晶振 + 32.768k RTC + 负载电容）、外置存储（QSPI NOR Flash / SPI NAND / SDRAM / eMMC 等 boot 与扩展存储接口的电源/电平/去耦）、BOOT 配置（strapping 电阻/跳线）、下载调试接口（SWD/UART、测试点）、去耦/滤波/ESD 防护、以及 BOM 关键器件 AVL 物料选型与合格供应商等完整参考电路与 BOM；
4. 文档定位：最小系统参考电路，是原理图 AI 审图、PCB 规范校验、设计参考、故障分析的权威事实源头之一；与芯片 datasheet / 用户手册互补，不冲突。

## 一、核心任务目标
1. 将最小系统原理图 PDF 经 EDA 矢量文本提取，结构化拆解为元件位号、参数、网络标号、引脚映射；
2. 在 `wiki/mcu/all/sources/` 新建来源页，绑定 raw PDF 双链；
3. 将最小系统各电路模块（电源树、复位、时钟晶振、外置存储、BOOT、调试接口、去耦/滤波/ESD 防护）作为参考电路，增量更新对应 `peripheral/` 外设页与 `chip_entity/` 芯片实体页；
4. 提炼最小系统设计强制要求，生成 `design_rules/` 设计规范；
5. 生成 `check_rules/` 最小系统审图规则（供 PDF 原理图 AI 审图程序直接调用）；
6. 记录已知坑点至 `fault_case/`；
7. 更新 `index_MCU_ALL.md` 与 `log_MCU_ALL.md`，输出自检清单。

## 二、全维度提取拆解范围
### 1. 原理图结构化提取（先执行 EDA 文本提取）
- 调用仓库根目录 `EDA原理图PDF识别提示词.md` 流程：优先 pdfplumber 矢量文本（方案A），检测失效后切换 PaddleOCR（方案B）；
- 提取要素：元件位号（R/C/U/L/D/Q…）、参数（阻值/容值/型号/耐压）、网络标号（VCC/GND/3V3/USB_D+…）、电源地标识、引脚编号、差分/总线标识；
- 输出结构化 JSON（含页码、坐标、置信度、可疑标记），禁止脑补虚构电路或参数。

### 2. 最小系统电路模块 → Wiki 映射
- 电源树（BUCK/LDO/各电源域/去耦）→ `peripheral/SF32LB52X_Peripheral_Power.md` + `design_rules/DR_PowerArchitecture.md` + `check_rules/CR_PowerDomains.md`；
- 复位电路（POR/BOR/nRST 外接）→ `chip_entity` §复位系统 + `check_rules/CR_Reset_Levels.md`；
- 时钟/晶振（48M 主晶振 + 32.768k RTC + 负载电容计算）→ `peripheral/SF32LB52X_Peripheral_Clock.md` + `check_rules/CR_XTAL48M.md`；
- BOOT 配置（strapping 电阻/跳线/电平）→ `design_rules/DR_BootMode.md` + `check_rules/CR_BootMode_Register.md`；
- 下载调试接口（SWD/UART 引脚、测试点、上拉）→ `peripheral/SF32LB52X_Peripheral_USB.md` + `design_rules/DR_Debug_Interface.md`；
- 外置存储（QSPI NOR Flash / SPI NAND / SDRAM / eMMC 等 boot 与扩展存储接口的电源/电平/去耦，MPI/SDMMC 引脚互斥）→ `peripheral/SF32LB52X_Peripheral_Memory.md` + `design_rules` + `check_rules/CR_SDMMC_MPI2_Exclusive.md`；
- AVL 物料（BOM 关键器件选型、合格供应商、替代料）→ 关联 `raw/mcu/vendor/device_spec/` AVL 入库，补充最小系统关键元器件选型与供应商约束；
- 去耦/滤波/ESD 防护 → 对应 `design_rules` / `check_rules`。

### 3. 生成设计规范（design_rules）
最小系统必选电路清单、推荐器件参数、去耦电容取值、晶振负载电容计算、BOOT 上拉/下拉电阻、调试接口保留焊盘等。

### 4. 生成审图规则（check_rules，关键产出）
- 最小系统缺失项（缺 RTC 晶振、缺去耦、BOOT 悬空、调试接口无测试点等）→ 致命/严重级规则；
- 参数超限（晶振负载电容偏大、分压源阻抗超限、VDD_RET 容值不符等）→ 严重/一般级；
- 每条规则绑定本来源页溯源，标注风险等级（致命/严重/一般/优化建议）、整改方案、知识库依据（格式对齐 AGENTS_MCU_ALL 第 11 条）。

### 5. 故障案例（fault_case）
最小系统常见失效（不起振、无法下载、复位异常、hibernate 漏电）的硬件根因与整改，绑定对应 MCU 型号与外设，区分参考设计与量产强制标准。

## 三、标准执行步骤（顺序不可打乱）
### 步骤1：全库预检索查重
1. 检索 `wiki/mcu/all/sources/`，确认本最小系统原理图是否已归档，避免重复建页；
2. 检索 `wiki/mcu/all/chip_entity/` 定位目标 MCU 芯片实体页面；
3. 预加载相关 `peripheral/`、`design_rules/`、`check_rules/` 页面，准备增量补充。

### 步骤2：EDA 原理图 PDF 文本提取
依 `EDA原理图PDF识别提示词.md` 生成结构化 JSON（方案A 优先），作为后续拆解的事实依据；保留页码/坐标用于溯源。

### 步骤3：新建来源索引页 wiki/mcu/all/sources/
使用 `_template.md`（type: mcu_source）新建页面：
1. 绑定 raw 最小系统原理图双链，填写 MCU 型号、版本、发布日期、页数；
2. 摘要说明文档定位：最小系统参考电路，非量产强制标准；
3. 记录核心电路章节、关键元件/网络页码索引；
4. YAML 元数据完整填充：`mcu_family`、`mcu_model`、`sources`、`tags: ["最小系统原理图","参考设计","ref_design"]`；
5. 双向关联对应 MCU 芯片实体页。

### 步骤4：更新对应 MCU 芯片实体页 wiki/mcu/all/chip_entity/
1. 新增板块「最小系统参考电路」，写入电源树/复位/晶振/外置存储/BOOT/调试要点，标注为参考方案；
2. 建立双向双链关联最小系统来源页。

### 步骤5：批量更新外设专项页面 wiki/mcu/all/peripheral/
针对电源/时钟/外置存储(MPI/SDMMC)/GPIO/USB(调试) 等页，补充本原理图参考电路、位号、参数、网络，标注来源；明确区分「参考设计演示」与「量产强制标准」。

### 步骤6：新增设计规范 wiki/mcu/all/design_rules/
提炼最小系统必选电路、推荐参数、去耦/负载电容取值、BOOT 上拉下拉、调试接口保留焊盘等设计规范。

### 步骤7：新增最小系统审图规则 wiki/mcu/all/check_rules/
针对最小系统缺失项与参数超限，新增审图规则，绑定来源页溯源，供 `review_schematic/` 审图程序直接调用。

### 步骤8：更新故障案例库 wiki/mcu/all/fault_case/
将最小系统常见失效（不起振/无法下载/复位异常/漏电）的硬件根因与整改存入，绑定 MCU 型号与外设。

### 步骤9：更新全局导航与变更日志
1. 修改 `index_MCU_ALL.md`，在 SF32LB52X 家族段或「参考设计」分类补充最小系统原理图入口，链接来源页与对应 MCU；
2. 在 `log_MCU_ALL.md` 尾部追加操作记录，固定格式：
`YYYY-MM-DD | 导入资料：最小系统原理图raw完整路径 | 新建页面：页面清单 | 更新页面：页面清单 | 待人工确认：最小系统电路与量产规范冲突明细`

### 步骤10：双链闭环自检
校验所有新建、修改页面双向关联双链，无断链、无效链接。

## 四、强制执行规则（对齐 AGENTS_MCU_ALL.md）
1. Raw 层最小系统原理图（`raw/mcu/ref_design/min_sys_sch/` 下）仅读取解析，禁止修改、移动、删除原始 PDF；
2. 所有电路、参数、网络必须标注来源（原理图页码/坐标）；描述模糊、缺少量化指标统一标记「待人工核实」并暂停，禁止自行编造硬件参数；
3. 最小系统电路与企业硬件设计指南、芯片手册存在冲突时，全部保留，明确区分优先级：芯片 datasheet / 用户手册 > 企业硬件设计指南 > 最小系统参考电路（演示/参考性质）；
4. 原有 Wiki 页面仅增量补充参考内容，不删除、覆盖历史规范，不修改其他 MCU 型号专属知识；
5. 所有页面必须使用对应分类 `_template.md` 标准模板，YAML 元数据必填字段完整；
6. 不生成网表、不做电气仿真、不解析电路走线/焊盘（遵循 EDA 提取规范，仅提取文字标注）。
